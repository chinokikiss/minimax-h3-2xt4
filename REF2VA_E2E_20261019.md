S1 completed 20 actual denoising evaluations, video decode and audio decode, then PyAV rejected a four-dimensional frame array. The native video tensor includes a leading batch dimension; the exporter iterated that dimension as if it were the frame axis. This was a benchmark-harness defect. S2/L1 did not start. The failed run saved audio and logs but no decoded frames or sampled latents, so its video cannot be recovered from the collected outputs.

Version 2 changes are limited to benchmark export, observations and orchestration:

- Accept T,H,W,C and single-request B,T,H,W,C; reject multiple-request batches. Local encode/decode tests confirm identical decoded frames for both supported layouts.
- Capture actual packed layout at attention consumption. Constructor hooks miss layouts created in the parent and copied to workers.
- Collect rank metrics on failure and save compact decode-input latents only when a failure occurs, enabling later recovery without repeating TE/denoising. Normal successful runs do not save these recovery tensors.
- Stream bounded stage/evaluation progress to notebook logs and download checkpoints with at most two concurrent workers.
- Use separate cold TileLang and CUDA driver cache directories per run to avoid granting S2 the compiled cache produced by S1. First-use compilation remains part of the explicitly cold generation measurements.

All production `patches/` source hashes remain identical to version 1. A version-bound collector retrieves saved videos, WAVs and metrics automatically after Kaggle exposes the completed session outputs. Local target: `semantic_results/ref2va_e2e_v2/`.

The job runs S1 → S2 → L1, with independent fresh rank processes, all 50 TE and DiT blocks, the native Ref2VA conditioning node, native sampler entrypoints, and public video/audio VAE interfaces. Outputs are H.264/AAC MP4 plus PCM WAV. Checkpoints and reference images are downloaded on Kaggle; the upload contains source and metadata only.

## Measurement boundaries and interpretation

- Foreground begins before VAE construction and includes reference encoding, TE, actual sampler evaluations, video/audio decoding and final MP4/WAV encoding. Downloads, service construction and S2's idle preload are reported separately.
- Report both foreground latency and preload-plus-foreground latency. Idle work is moved outside the foreground boundary; it is not eliminated.
- CPU checkpoint reads and preparation use monotonic wall time and thread CPU time. CUDA events measure GPU timeline spans, block consumer waits, execution and actual attention/LoRA entrypoints. A GPU timeline span containing CPU starvation is not pure kernel execution time.
- Existing bounded window counters provide H2D copy event durations, transferred bytes, host waits, cache hits and evictions. These overlap other spans and must not be summed as serial latency.
- Per-command per-rank allocator peaks and sampled NVML board usage are separate quantities. NVML covers the parent and worker contexts, allocator reservations and libraries; samples may miss very short peaks.
- Memory samples include process-level RSS and cgroup usage, file cache and pressure. Parent and worker allocations must be kept separate when interpreting GPU0.
- Fresh processes plus targeted checkpoint `POSIX_FADV_DONTNEED` are used before each run. Advisory eviction does not prove a physically cold backing store. No global cache drop or checkpoint deletion is performed.
- These are cold-generation experiments, not a repeated warm-latency distribution. First-use compilation/module loading can remain inside the request. No full generation is added for warmup, and no profiling-only denoiser evaluations are run. Differences cannot be attributed solely to idle residency without examining these confounders.
- Lightweight observers are enabled in these benchmarks only. Their host/event overhead is included in measured foreground latency. No separately measured profiler-overhead correction is claimed. Full Kineto/Nsight traces are not generated by default.

## Acceptance and artifacts

The job requires two physical SM75 T4s and checks actual Group32/scalar execution entrypoints. It saves each completed run before starting the next. S1/S2 conditioning, sampled latents, decoded pixels and waveform must have identical shapes/dtypes/SHA256 and finite values before L1 proceeds. This proves the idle-policy A/B preserves outputs; it is not a newly run dense Native reference comparison. L1's accepted approximate operators do not imply dense Native byte equality.

L1 is rejected if a measured rank denoising allocated peak reaches14.5 GiB. Runtime admission and native VAE memory controls remain active; an OOM or refused preload is a failed experiment, never a successful performance result.
