# H3 DiT P0-A1 / P0-C — Physical Dual-T4 Report (2026-11-02)

## Decision

**The physical two-T4 study completed. Numerical/dispatch gates passed;
memory wins are phase-local; performance non-regression is not certified.
Do not promote either experiment to production solely on these results.**

- **P0-A1** is a strong candidate: verified elimination of the unused
  Kitchen CUDA output buffer on real Turing kernels, bit-exact trained-block
  output, and lower QKV/FC1 phase peaks. It also lowers the stable maximum
  instrumented phase peak despite FC2 becoming the new bottleneck.
- **P0-C** is bit-exact on the actual SM75 packed/global-quantization
  pipeline at every tested shape and materially reduces O-Proj peak.
  FC1 still dominates the overall block, so **P0-C alone does not lower
  the stable block-stage maximum**. It has favorable warmed median
  timings in this batch, but is not an independently proven E2E win.
- **P0-A1 + P0-C** remains bit-exact. Its median block time is **0.87%
  slower** at 59,134 tokens and **3.11% faster** at 65,166 tokens. Five
  interleaved samples exhibit enough variation that a blanket
  zero-regression performance assertion would be unjustified.
- **P0-A2 / input-owner detach** was not part of this T4 A/B. The local
  view-alias lifetime objection remains unresolved. The retired P0-1
  implementation is not restored.

Production P0-2 and P0-3 remained enabled and unchanged throughout.
No production operator/default was edited and no Git push was made.

## Exactness and backend execution

All comparisons in the new worker use raw floating-point bit views
(including signed zero), not an arbitrary tolerance.

- Both ranks, S=59,134 and 65,166: final trained-block FP16 output
  for **P0-A1, P0-C, P0-A1+P0-C** versus baseline:
  **0 bit mismatches**, all finite.
- Both ranks and all S=128, 6,814, 59,134, 65,166:
  actual SM75 **P0-C** padded-versus-local ConvRot FP32 bytes,
  global FP32 scales and TileLang INT8 codes: **0 bit mismatches**.
- Every variant and shape executed the expected QKV and FC1 column
  paths. The P0-A1 arms recorded **22/22 successful real Turing CUTLASS
  calls per rank/shape** (11 block executions × QKV and FC1).
  The P0-C arms recorded **11 actual O-Proj quantizer calls per
  rank/shape**. The baseline P0-2 packed route was also hit.
- The earlier local RTX 5060 Ti S=128 rounding counterexample is not
  contradicted: this is a **different SM120 cuBLAS backend**. Exactness
  on physical SM75 is now directly observed for these inputs/shapes,
  but is not a universal numerical proof for every CUDA architecture.

## Allocated peak — real physical-T4 stage measurements

These are **phase-local peak differences** from matched before/peak
instrumentation in both ranks, not a claimed full-H3 E2E peak reduction.

| A/B and phase | S=59,134 reduction | S=65,166 reduction |
| --- | ---: | ---: |
| P0-A1 — QKV | **1,212.709 MiB (1.184 GiB)** | **1,336.412 MiB (1.305 GiB)** |
| P0-A1 — FC1 | **1,616.945 MiB (1.579 GiB)** | **1,782.000 MiB (1.740 GiB)** |
| P0-C — Attention O-Proj | **1,414.602 MiB (1.381 GiB)** | **1,559.133 MiB (1.523 GiB)** |

The stable, uncontaminated FC1/O-Proj/FC2 peak ledger shows:

| Qualified stable stage maximum | S=59,134 | S=65,166 |
| --- | ---: | ---: |
| Baseline (dominant FC1) | 5.459 GiB | 5.995 GiB |
| P0-A1 or P0-A1+P0-C (dominant FC2) | 4.576 GiB | 5.023 GiB |
| Maximum-stage reduction | **0.883 GiB** | **0.972 GiB** |

**P0-C alone does not reduce that maximum**: FC1 remains unchanged.
Combining P0-C with A1 also gives no additional maximum-stage reduction
in this tested block because FC2 becomes dominant. P0-C still lowers
the O-Proj working set and may help other execution schedules.

### Important allocator-accounting caveat

The instrumented whole-block max_memory_allocated pass is **not a
reliable normalized E2E peak comparison** in this run:

- At S=59,134, per-variant initial allocations unexpectedly ranged
  from **0.818 to 4.768 GiB** (a 3.949 GiB spread).
- At the S=65,166 baseline, the first norm/QKV phases were entered with
  excess temporary live allocations that disappeared later in the
  call; their absolute peaks cannot be compared directly with the
  stabilized A/B arms.

Accordingly, this report uses matched **phase peak minus phase-before**
deltas for individual operators, and a stable downstream-stage
maximum for the block-level bottleneck illustration. It does **not**
relabel a contaminated whole-call peak as a true full-H3 reduction.
A fresh consistently initialized whole-block/full-H3 pass is required
for a stronger global-peak assertion.

## Warmed block latency (physical two-T4 CUDA events)

Five interleaved repetitions per arm after warmup. The table uses the
**slower rank's median CUDA time**, rather than adding both ranks.
Negative percentage means faster.

| Variant | S=59,134 median | vs baseline | S=65,166 median | vs baseline |
| --- | ---: | ---: | ---: | ---: |
| Baseline | 2,863.76 ms | — | 2,624.84 ms | — |
| P0-A1 | 2,828.40 ms | **−1.23%** | 2,603.97 ms | **−0.79%** |
| P0-C | 2,841.94 ms | **−0.76%** | 2,557.18 ms | **−2.58%** |
| P0-A1 + P0-C | 2,888.76 ms | **+0.87% slower** | 2,543.18 ms | **−3.11%** |

The five raw samples drift markedly at S=59,134 (e.g. baseline from
approximately 3,075 to 2,690 ms). Variability is much larger than a
sub-1% margin, and combining the kernels is not monotonically faster.
This data does **not** satisfy a formal guaranteed no-regression claim.
The delivered per-rank JSON retains every sample, wall time, baseline,
compilation gate and phase observation.

identical initial allocation state and sufficient balanced warmed

no-online-LoRA scope, frozen sources and P0-2/P0-3. Do not silently
apply the optimized path on unsupported geometries or devices.
