## Storage admission hardening

Before future model downloads, `benchmarks/ptd_storage.py` now allocates the
entire conservative **258,523,593,608-byte (240.77 GiB)** requirement on the
selected scratch filesystem with `posix_fallocate`. It checks allocated blocks,
writes and reads both ends, and requires successful `fsync` before releasing
the probe file. Sparse-file fallback and suppressed sync errors are rejected.
This is a point-in-time allocation check; releasing the probe does not reserve
space against later users or guarantee subsequent writes.

The CPU gate requests the same check without downloading weights or using a
GPU. The GPU run repeats it on its own allocation; CPU storage success does not
qualify a different GPU instance. CPU gate failures block GPU submission.
The bounded notebook watchdog applies to the allocation operation as well.

On a later run failure, the harness records filesystem/inode/device data,
mount information, logical and allocated file totals, the failed stage, and a
small archive of partial bank receipts. Weight payloads remain on scratch.
Native merge validation, hash verification and durable publication are unchanged.
