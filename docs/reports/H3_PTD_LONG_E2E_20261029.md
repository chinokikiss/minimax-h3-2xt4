## Execution and memory

1. CPU setup qualifies the frozen legacy ComfyUI source, Kitchen 0.2.37 and
   TileLang 0.1.13 against Kaggle's native Torch/CUDA family. Core signatures,
   real Native guider/sampler integration and reference-image hashes are checked
   without fetching model/LoRA payloads or using GPU time.
2. On two physical SM75 T4s, verify RAM/disk/compiler/device admission before
   downloading public immutable base shards and the full 11.11 GB PTD file.
3. Bake eight complete INT8 TP2 experts with independent Native merge checking.
   Persist all shards and trusted receipts under `/tmp/h3_ptd_e2e_20261029`.
   Use a separate bake process, which exits before generation begins.
4. Stream the bank through the existing append-only queue. Keep future-use CPU
   reclamation and next-refiner CPU prefetch; retain all integrity checks.
   GPU residency remains bounded; all eight experts are never GPU-resident.
5. Run one complete request, save `decode_inputs.pt` before decoding, then
   export the MP4 and WAV. Save compact per-hop state/output summaries, backend
   evidence, stage timings, memory samples, source identity and bake receipts.

The conservative estimate is **182,727,920,384 bytes (170.18 GiB)** for eight
expert banks and **258,523,593,608 bytes (240.77 GiB)** initial free scratch
including base/TE/VAE/PTD inputs and headroom. Actual admission is recomputed
on the device. Input models and partial banks stay in job-local scratch; large
model files are not notebook outputs.

Each rank retains the existing **9 GiB activation reserve**, 6 GiB weight-window
cap and 6 GiB pinned-memory cap. CPU cache is 4 GiB per rank, sufficient for the
roughly 3 GiB refiner plus a block, with a shared 20 GiB host budget. Require at
least 27 GiB usable host RAM; cgroup limits are included. The existing
pressure-aware admission, asynchronous-copy lifetime protections and adaptive
lookahead remain enabled.

The GPU execution watchdog is 10,800 seconds, covering staging, eight-bank bake
and generation; the notebook timeout is 11,700 seconds including setup/margin.
Individual bake/generation limits are 6,300/3,600 seconds. These are termination
bounds, not predicted runtimes. A timeout preserves logs/receipts and completed
output checkpoints instead of submitting another job automatically.

## Preservation and validation

This is a benchmark-only overlay on the already qualified P2 capsule. Runtime
patches, Native source, attention APIs, core pins and existing defaults remain
byte-exact. The only replacement is the benchmark observer's existing fix that
tags every RPC, including Temporal decode, so decoder attention is not counted
as DiT attention. New dedicated PTD orchestration avoids invoking the historical
Turbo runner's main entry point.

Local checks used the normal `conda comfyui` interpreter, frozen source and
`CUDA_VISIBLE_DEVICES=-1`, with no real LoRA download:

- 179 existing CPU contracts: pass, zero skips.
- 41 PTD/queue/cache/attention-observer/E2E contracts: pass. The new test actually
  calls Native `CFGGuider.sample` and `KSAMPLER` with tiny CPU nested latents,
  checks eight ordered expert calls, raw FP32 TE payload preservation, audio
  clock adaptation, session cleanup and the FP32 state recurrence.
- The full CPU qualifier also verified both original reference-image hashes.

These tests establish wiring and preservation only. Full-model T4 memory,
latency, media quality and all-eight-hop execution remain unqualified until the
new GPU job completes.
