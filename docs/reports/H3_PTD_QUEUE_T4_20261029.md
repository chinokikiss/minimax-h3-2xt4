# PTD persistent queue: physical two-T4 comparison

The bounded fixture passed on two physical Tesla T4 GPUs. Queued handoff preserved byte-identical outputs and reduced the measured eight-hop selection-plus-denoiser RPC total by **24.2%**. It still waits heavily for CPU weight preparation; eliminating teardown has not produced continuous GPU execution.

## Scope and reproducibility

Kaggle notebook: [H3 PTD TP2 T4 20261028, version 2](https://www.kaggle.com/code/pamcks/h3-ptd-tp2-t4-20261028). Outputs collected on 2026-10-29, Asia/Shanghai. Source commit `b6d094d391ecaec4dc89feacb32abe23b912f0ad`, capsule `595eddf8be6f4cecd46d67a9792d49283488e29d9de2933fca8c367c6dead6bf`. Native ComfyUI source, legacy APIs and exact core pins are unchanged. Runtime: native Torch 2.11.0+cu128, CUDA 12.8, Kitchen 0.2.37, TileLang 0.1.13.

One trained subset was baked once, then used in rebuild / queue / queue / rebuild order. Each case creates a fresh service. The fixture has two trained DiT blocks, both refiners, complete video/audio head banks and all eight PTD hops. Inputs are identical seeded small operator inputs: 24 packed tokens, four text tokens, video `[1,24,1,4,4]`, audio `[1,32,2,8]`; seed 20261028. The current pruned AdaLN approximation is explicitly enabled. TE, VAE and full H3 generation do not execute.

The reported execution total sums parent hop-selection and denoiser RPC durations. It excludes source/model downloads, baking, AOT, service construction/configuration, diagnostic state/stats queries and final teardown. It is neither a sampler wall-clock measurement nor full-pipeline latency. Two repetitions per method and ABBA order reduce some startup/order bias, but do not remove page-cache or memory-pressure variation.

## Correctness and completion

- All 19 PTD/queue contracts passed on the GPU host.
- Eight reduced banks baked in **272.48 s**, with **128 independently Native-verified merge-target checks** and 18,636,426,752 bytes written.
- All four cases completed hops 0–7: **32 denoiser calls total**. Video/audio output hashes match at every hop, and final FP32 carried-state hashes match across all cases. Outputs are finite.
- Each queue case retained exactly one model shell and residency window across all eight hops.
- Every rank/case has all 16 completed worker spans: eight hop selections and eight denoiser calls, with resolved CUDA event intervals. Worker JSON was persisted before stats acknowledgement. The supervised experiment exited normally after 1,086.39 s.
- The reduced bank is rejected by production admission as intended. This verifies handoff equivalence; it does not establish trained PTD generation quality or full-model accuracy.

Mean eight-hop RPC totals are **148.561 s rebuild vs 112.674 s queue**: 35.887 s saved, **24.2% lower latency**, or 1.319× measured rate. Excluding initial hop 0 gives **136.836 vs 99.042 s** for hops 1–7, **27.6% lower latency**. These later hops use different experts; excluding initialization does not make their weights fully resident or establish steady-state deployment performance.

Pooled median selection RPC time for hops 1–7 falls from **10.610 s to 8.584 ms**. Pooled median denoiser RPC time rises from **8.987 s to 14.213 s**. The queue moves lazy preparation into denoising and avoids part of the repeated setup, so the selection-only ratio overstates the improvement. The combined total is the appropriate comparison here.

First AOT preparation is cold while later cases benefit from the existing compiler cache. AOT remains separate in the table; its difference is not credited to queued handoff. The receipts show the corrected **96/128 rotary layout** was prepared on SM75. They do not by themselves prove zero runtime first-use work.

| Rank 0 H2D bytes over eight hops, GiB | 26.737 | 26.739 |

CUDA figures are PyTorch allocation/reservation high-water marks, not total device usage including context/external allocators. Host-budget reservation is a logical admission metric, not RSS. RSS snapshots are available in the original worker reports, but are not measured process peaks. Counters from both ranks, the host cache and the residency window overlap and must not be added as independent latency components.

The persistent queue saves setup while doing nearly the same H2D traffic. Its rank-0 copy-event intervals total 6.30–6.48 s, compared with 74.68–81.43 s of window host waits. The retained GPU window is bounded and there was no CUDA OOM; the stronger concern is CPU preparation/cache residency and transfer of each new refiner. The queue retains more CPU blocks than the rebuild path and the cgroup snapshots contain memory-pressure/reclaim evidence. Those snapshots do not prove how much latency was caused by reclaim.

Source inspection shows three concrete next targets:

1. **Retire consumed CPU cache entries while preserving future queued groups.** Appending should retain the active/future horizon, rather than retaining already-consumed expert blocks merely because the cache has space. Verify CPU admission/ownership and avoid weakening event lifetime guards.
2. **Break down and schedule CPU preparation earlier.** The queued path still verifies each full auxiliary overlay on first consumption, loads/casts/folds refiner matrices, and prepares blocks through bounded CPU workers. Add per-stage timings before attributing the 75–81 s wait specifically to checksumming, I/O, folding or scheduling. Consider immutable tensor-level integrity proofs to avoid reading unrelated overlay payloads on rank 1, while retaining validation.
3. **Then evaluate chunked/pinned refiner transfer.** The pageable group avoids a second multi-GiB pinned copy but may stage synchronously. Transfer improvement alone cannot remove the much larger observed host-preparation waits; measure it after CPU scheduling and memory retention are controlled.

Window compute/copy CUDA events and default-stream RPC intervals include waits, CPU launch gaps or rank synchronization; they are not summed kernel execution times. No Nsight Systems/Compute trace was produced in this fixture. Kernel, disk, checksum and NCCL attribution remain unseparated.

## Decision and evidence

Keep the bounded queue for the optional PTD adapter and retain explicit rebuild for comparison. Native PTD-disabled defaults are unchanged. Do not interpret the 24.2% fixture result as a full-model or long-sequence speedup, and do not claim generation quality from hash equivalence between two handoff paths. No additional GPU job was submitted during this collection.
