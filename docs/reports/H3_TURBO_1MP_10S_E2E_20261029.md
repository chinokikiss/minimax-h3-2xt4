Both actual distinct devices were Tesla T4, SM75, on native Torch
`2.11.0+cu128` / CUDA `12.8`, Kitchen `0.2.37`, TileLang `0.1.13`. Source and
download hashes match the qualified capsule. Offline dual-GPU baking completed
in **334.92 s**, validated all **208 targets**, and persisted **21,237,118,728
bytes**. Its own original DiT payload copies were released as planned. This
failure was GPU activation memory, not the earlier PTD disk-capacity failure.

Reference processing and TE completed. The first sampler call failed at
`tp_dit.py -> out_proj -> tilelang_transport_p2.row_linear ->
tilelang_row_quant.global_row_quantize -> Kitchen _rotate_activation ->
torch.matmul`. The attention-output quantization rotation requested **2.09
GiB**, with **1.75 GiB free** on a **14.56-GiB** GPU. PyTorch reported **9.47
GiB allocated** and **2.55 GiB reserved but unallocated**. Those allocator
figures alone do not prove fragmentation as the cause; no allocator-setting
experiment was performed.

Zero denoiser calls and sampler steps completed, so video/audio decoding and
export were not reached and no final replay latents were available. The full
E2E subprocess ran **309.35 s** before failure. Raw failed results, bake receipt,
exceptions, setup identities and memory observations are retained under
`docs/data/h3_turbo_1mp_10s_20261029/gpu_v1_final/`.
